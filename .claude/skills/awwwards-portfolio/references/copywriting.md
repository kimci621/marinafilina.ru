# Текст для портфолио

Общие принципы письма (активный залог, конкретика вместо общих слов, голос интерфейса для ошибок/пустых состояний) — см. секцию "Writing" в skill `frontend-design`. Здесь — то, что специфично для структуры сайта-визитки.

## Hero

Один тезис, не список услуг. Формула: **что делаешь + для кого/как именно** — конкретика вместо "innovative solutions".

- Плохо: "Creative Designer crafting innovative digital experiences."
- Лучше: "Проектирую интерфейсы для fintech-продуктов, которым доверяют деньги." / "Делаю бренды, которые не стыдно поставить рядом с Bloomberg."

Хедлайн должен быть тем, что реально отличает этого дизайнера — тяни формулировку из "3 слов" бренда из `brief-questionnaire.md`, не из общего словаря дизайн-индустрии.

## About

Пиши от первого лица, конкретными фактами (годы опыта, конкретные индустрии, 1-2 узнаваемых клиента/проекта), а не эпитетами ("passionate", "dedicated"). Один абзац — что делает, один — как работает (процесс), один — с кем хочет работать дальше.

## Кейс проекта

Структура **задача → подход → результат**, коротко на каждый пункт (3-5 предложений):

1. **Задача**: что было не так / зачем клиент пришёл. Конкретная проблема, не "нужен был редизайн".
2. **Подход**: 1-2 ключевых решения, которые приняли, и почему. Не пересказ всего процесса — самое нетривиальное решение.
3. **Результат**: измеримый эффект (конверсия, скорость, отзыв клиента) если есть; если метрик нет — честно показать до/после визуально, не выдумывать цифры.

Заголовок кейса — не название проекта, а суть результата: "Redesign for Acme" слабее, чем "Как редизайн чек-аута поднял конверсию на 18%" (если это правда).

## CTA / Контакты

Одно ясное действие на футер, названное тем, что реально произойдёт: "Написать на почту", "Забронировать созвон" — не "Get in touch" ради общности, если реальный канал — конкретная почта или календарь.

## Красные флаги шаблонного текста

- "Innovative", "cutting-edge", "passionate", "seamless experiences" — общие слова без содержания, вырезать.
- Заголовки-вопросы без ответа ("Ready to elevate your brand?") — заменить на утверждение с фактом.
- Кейс без конкретной проблемы/решения — превращается в галерею скриншотов без истории.
